# 长期目标与组件完成刷新

用户希望设定长期目标的截止日期，将目标拆成多个各有截止日期的阶段；组件点击完成后直接归入下方，不反复闪动。沿用本会话“直接实现”的授权，设计、实现与发布连续完成。

## 长期目标

- 今天页面增加“长期目标”入口。列表按未完成、已完成分组，显示标题、截止日期、完成阶段数及进度。
- 新增/编辑目标填写标题、总截止日期；至少一个阶段，每阶段填写标题、截止日期。使用“添加阶段”增添，不强迫预先指定数量。阶段不得晚于总截止日期。
- 阶段复用普通计划实体，仅新增可选 goalID、deadline。goalID 指向独立的 PlannerGoal；deadline 保留原定截止日，date 为实际执行日期。这样现有组件完成、提醒、排序、保存、备份均共享同一份完成状态，不复制任务。
- 到阶段日期进入当日计划，未完成沿用普通计划顺延，但不改阶段截止日；可从目标详情提前完成/撤销。所有阶段完成即目标完成；没有阶段不算完成。
- 编辑目标保留原阶段 ID、完成状态、重要标记、提醒。删除阶段会在保存时删除对应计划，编辑已有阶段移除需确认。删除目标需确认并同时删除阶段。阶段不能转为每日重复；普通计划编辑器可改内容、重要、提醒与执行日期，截止日期在目标编辑器改。
- 完成任务不删除；全局拖动顺序不影响目标中按阶段截止日期的展示。
- 旧备份 goals 缺省为空，旧任务无关联；拒绝重复目标 ID、空标题、无效日期、悬空关联及阶段超过总截止日期的备份。

## 组件

源码发现冷加载 publish 旧状态，随后保存 publish 最终状态，再 Intent 显式 reload；系统自身在 Intent 结束还会 reload。两个 ForEach 将完成前后的行变成不同身份，触发默认淡入淡出。

- 将 widget completion 的冷加载、跨天、保存出版合并，只发布已持久化的最终状态。
- Widget 操作的出版仅写共享文件；系统在 Intent 返回后负责唯一刷新。App 内编辑继续显式 reload。保留失败反馈、重试与 generation 检查、唯一主 App 存储写入者。
- 使用单一稳定 ID 的 ForEach，同一行完成后移到列表尾部；取消默认淡入淡出/数字变化、等待遮罩和乐观 Toggle 中间态。使用圆圈 Button 提交持久化完成后更新。
- 空间有限时优先显示最近完成的计划，避免刚完成项目被旧完成项挤出；待完成沿用 App 手动排序。
- Apple WidgetKit 限制仍适用，不能承诺主屏任意帧刷新或零延迟。代码、模拟器与真实 iPhone 手感分开验收。

## 验证

Core 覆盖旧备份兼容、关联持久化、顺延不改截止日、非法阶段、目标编辑保留完成状态、删除与撤销。App 覆盖冷/热 widget 仅最终出版、保存失败重试、目标跨重启与提醒。UI 覆盖目标新增、阶段完成、编辑、重启。全部现有测试与 arm64 App/Widget 打包通过后发布 1.4.0，更新说明与安装包。
