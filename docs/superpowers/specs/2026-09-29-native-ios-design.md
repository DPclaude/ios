# 计划本：完全原生 iOS 版设计

日期：2026-09-29。状态：用户已回复“按这个设计做”，设计已批准；SwiftUI 原生实现已进入云端回归验收，最新结果见 docs/ios-acceptance.md。

## 用户目标与范围

用户明确要求：把 GitHub 上的计划本做成完全原生 iOS 软件，交互像 iOS 一样流畅；使用 iPhone 14 Pro、iOS 27.0；没有 MacBook；费用尽量免费；希望自动续签。

已取得源代码：https://github.com/DPclaude/ios ，基线提交 `906a21d`。

首版按个人自用设计，这是当前假设。成功标准是生成可由免费账户签名安装的 IPA，迁移原有计划数据，核心操作完全使用 SwiftUI 原生界面，并在用户手机上完成安装、离线使用和续签验证。

## 方案选择

采用 SwiftUI 重写界面和业务逻辑；不使用 WKWebView、HTML 或 JavaScript 运行计划功能。混合式包装已被用户否决。

在现有仓库新增 `native/Planner/`；原有网页入口继续可用，作为导出旧数据的来源。构建使用 GitHub Actions 的标准 macOS 运行器。首版不引入后端、订阅或付费 SDK。

SwiftUI 系统组件承担导航、列表、编辑表单、菜单、文件选择及分享。持久化采用本地 Codable 数据文件和串行存储 actor，避免首版引入数据库迁移与免费签名无关的云服务依赖。若性能测量证明数据规模超出文件方案承受范围，再评估数据库；本次不预先扩展。

## 界面与操作

视觉方向：接近系统提醒事项与日历的简洁布局，系统字体、系统背景与圆角，橙色作为计划本强调色。适配安全区域、深色模式、动态字体、VoiceOver 和“减弱动态效果”。使用系统提供的材质，不手工堆叠大面积模糊。

主页面以当天日期为标题，上方显示一周日期入口和当天完成进度，下方是原生任务列表。可以选择某天、前后切换日期、打开系统日期选择器及返回今天。日期切换不抢占列表侧滑删除和系统返回手势。

分类保留“默认、工作、私事、学习”，支持全部及单分类筛选；进度仍计算当天所有分类的任务。未完成与已完成任务分区，已完成区可折叠。

底部提供快速添加入口；点按进入系统编辑面板，自动聚焦输入，可选择分类、日期和每天重复。提交后可继续添加，避免每次操作都重复开关键盘。

点击任务内容进入原生编辑表单；点击完成圆圈切换完成状态，使用短促、可中断的动画及轻触反馈。支持侧滑删除、普通任务置顶和移到所选日期的下一天。删除后显示 7 秒撤销入口；撤销只恢复所删项目，不回滚期间其他编辑。

当天备忘使用原生多行编辑，自动保存，按日期独立存储。设置页面提供导入、导出、版本信息和安装／续签说明。

## 业务规则与兼容性

- 普通任务保留原有 `id、text、date、done、cat、order、doneAt、rolled` 语义；旧字符串 ID 不强制转换成 UUID。新 ID 可使用 UUID 字符串。
- 每日重复规则保留 `id、text、cat、from`；每日完成状态保留 `repeatDone[日期] = [规则ID]`，不为未来无限生成任务。
- 尚未完成且日期早于今天的普通任务，在启动、回到前台、本地日期发生变化时顺延到今天并标记“顺延”；已完成任务和未来任务不变。操作幂等。
- 从普通任务转为重复任务时，以当前所选日期为开始日期，并保留当天完成状态。取消重复与旧版一致：移除规则，在当前所选日期保留一条普通任务；明确告知该操作影响整条规则。
- 编辑重复任务修改整条规则；删除重复任务删除整条规则。使用明确文案，不把它伪装成只删除当天。
- 90 天前的重复完成记录按旧版规则清理；普通已完成任务及日记不自动清理。
- 置顶沿用普通任务 `order` 排序含义；重复项沿用虚拟顺序 -1；同序项目有稳定的确定顺序。
- 日期使用本地日历日计算，存储为 `YYYY-MM-DD`；完成时间沿用 Unix 毫秒。以公历处理备份日期，跨月、跨年、闰日、夏令时与时区变化均覆盖测试。

## 数据保存与旧版迁移

原生数据存于应用沙盒 Application Support；带内部格式版本号。文件读写、备份解码和编码交给串行存储 actor；UI 状态在主线程管理。使用原子替换避免半写文件，串行化写入避免旧快照覆盖新快照。

任务变更立即排队保存；备忘编辑短暂防抖，离开编辑、切换日期或进入后台时提交待保存内容。存储失败时保留内存内容并明确提示“尚未保存”，支持重试与导出；不会用空数据覆盖读取失败的文件。

从网页版“导出备份”生成 JSON，在原生版系统文件选择器中导入。无法直接读取 Safari/PWA 的 localStorage，因此不能承诺自动迁移。导入流程：读取和校验 → 展示项目数量及覆盖说明 → 保存当前数据的恢复副本 → 原子替换 → 更新 UI。用户取消或任一校验／保存失败时不改变现有数据。

兼容旧版顶层 `tasks、notes、repeats、repeatDone`；缺少可选字段时使用与旧版一致的默认值。校验日期、类型、分类编号、ID 唯一性与重复完成关联；损坏的数据明确报错，不静默丢弃任务。处理已删除规则留下的完成引用时可忽略这些无效引用，但不丢弃有效规则的完成状态。

导出继续提供与旧版兼容的 JSON，可存入系统“文件”或通过分享面板传出。内置的恢复副本随卸载而消失，界面应说明外部备份的重要性。

## 流畅度实现与验收

使用原生 List、稳定项目标识及局部状态观察，不在每次勾选时重建整页。视图 body 内不执行文件 I/O、JSON 编码或反复全量排序；按日期构建展示结果，仅在数据或筛选发生变化时更新。

滚动、键盘、导航和编辑面板使用系统交互；仅对完成、删除、日期选择和进度变化添加适量动画。动画可被连续操作中断。尊重系统节能与减少动态效果设置，不创建空转计时器强行维持高帧率。

iPhone 14 Pro 的 ProMotion 由系统按负载、温度、电量和内容调度，不承诺始终固定 120 fps。流畅度需要 Release 版本的真机测量与体验，云端模拟器成功不能替代真机验收。

基准数据包含正常数据集（总计 1,000 条普通任务、30 条重复规则）以及压力数据集（10,000 条普通任务、当天 300 条任务）。检查连续滚动、快速完成多项、分类切换、日期切换、连续输入备忘、打开关闭编辑面板及后台恢复。

验收目标：正常数据下交互反馈在下一次可用显示更新开始；不得出现可重复、用户可感知的主线程停顿。可使用 Instruments 时记录 SwiftUI 更新、动画卡顿和主线程耗时，对交互期间超过 100ms 的工作逐项排查。没有真机分析权限时明确标记性能验收待完成，不声称已验证 120Hz 或“零掉帧”。

## 构建、安装与续签

以支持系统外观的当前稳定 Xcode SDK 构建；部署目标设为 iOS 17.0，明确覆盖目标设备的 iOS 27.0。CI 固定已验证的 macOS/Xcode 组合，在运行日志输出实际版本，不能仅依赖浮动 latest。实现时核实可用镜像后锁定版本。

构建流程：业务单元测试 → iOS 模拟器 UI 冒烟测试 → 真机 Release 编译（关闭 Apple 代码签名）→ 将 `.app` 打包为 `Payload/Planner.app` 的 IPA → 上传 Actions 构建产物。该 IPA 需要 SideStore 签名后才能安装，不宣称可直接点击安装。固定 Bundle ID `com.dpclaude.planner`，显示名“计划本”。

公开仓库标准 GitHub 托管运行器可免费使用；控制构建触发范围、并发和产物保留时间，不启用收费大型运行器。云端不保存 Apple 账户密码、配对文件或个人备份。

SideStore 在 Windows 首次辅助安装，用户在自己的设备或官方工具中完成 Apple 登录、双重认证、信任与必要的开发者模式步骤。应用签名和自动续签属于 SideStore 的职责；计划本自身不能在后台给自己续签。

按 SideStore 当前官方流程配置本地 VPN、Wi-Fi 与后台刷新。先人工完成一次刷新，确认计划本有效期延长，再根据安装版本提供的快捷指令动作设置每日刷新自动化，提前多天重试。必须验证手机锁屏条件下能否执行；若动作不可用，使用官方后台刷新并说明限制。

免费签名通常 7 天有效，免费账户同时安装应用数量受限；SideStore 本身占用一个名额。网络、后台调度、Apple 服务和工具兼容性都可能使续签失败。不能承诺永不失效，也不把 Codex 定时提醒当成续签。失败时保留数据并提供手动刷新／重新签名恢复路径，避免首先要求删除 App。

软件升级需要安装新 IPA；签名刷新仅延长有效期，并不自动更新产品版本。提供版本号与构建下载入口，避免沿用网页的刷新即更新机制。

## 模块边界与交付物

- `PlannerCore`：日期、数据模型、重复规则、排序、顺延、导入校验及备份编解码，可独立测试。
- `PlannerStore`：串行文件存储、保存状态和恢复副本；不包含 UI。
- `PlannerApp`：SwiftUI 启动、当天清单、编辑面板、备忘、设置和系统文件交互。
- `.github/workflows/`：测试、编译和 IPA 产物工作流。
- 中文安装与数据迁移说明，以及经过手机验证后填写的续签验收记录。

首版不新增账户体系、云同步、提醒推送、桌面小组件、协作或自定义重复周期。这些不是当前功能，不为实现流畅的原生版而引入额外范围。

## 验证与完成定义

现有网页回归测试继续通过。原生测试覆盖顺延幂等性、日期边界、普通／重复完成切换、重复转换、取消重复、删除撤销与期间新增编辑共存、排序、分类统计、旧 JSON 迁移、非法导入不覆盖、备份往返及乱序保存防护。

云端至少完成一次模拟器核心流程和真机 Release 编译，并取得可下载 IPA。模拟器 UI 检查新增、完成、编辑、删除撤销、日期切换、深色模式与大字体。

真机必须检查首次安装、旧数据迁移、无网络使用、关闭重开后的数据保持、导出备份以及一次续签后数据仍在。自动续签还需观察实际自动化触发结果。未完成的手机步骤在交付中逐项说明，不能把“工程已写好”称为全流程完成。
